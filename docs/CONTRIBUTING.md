# 팀 협업 가이드라인

## 브랜치 전략
- `main`: 프로덕션 브랜치 (배포 가능한 상태)
- `develop`: 개발 통합 브랜치
- `feature/기능명`: 새로운 기능 개발
- `hotfix/수정명`: 긴급 버그 수정

## 커밋 메시지 규칙
- feat: 새로운 기능
- fix: 버그 수정
- docs: 문서 수정
- style: 코드 스타일 변경
- refactor: 리팩토링
- test: 테스트 추가/수정

예시: `feat: 이벤트 리스트 페이지 구현`

## 코드 리뷰 프로세스
1. feature 브랜치에서 작업
2. develop으로 Pull Request 생성
3. 최소 1명의 리뷰어 승인 필요
4. 모든 테스트 통과 후 머지
